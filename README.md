# Speedtest CLI

Консольная утилита на Node.js: последовательно скачивает указанный URL заданное
число раз, дожидается полного тела ответа и считает среднее время запроса,
суммарный объём скачанных данных и скорость скачивания.

## Требования

- Node.js 18+ (используются встроенные `fetch` и `AbortSignal.timeout`).
- Проверено на Node.js 22.
- Внешних зависимостей нет, поэтому `npm install` не требуется.

## Запуск

```bash
node index.js <URL> [опции]
```

Или через npm:

```bash
npm start -- <URL> [опции]
```

Пример с большим файлом:

```bash
node index.js 'https://speed.cloudflare.com/__down?bytes=10000000' --request-count 10
```

Кавычки нужны, потому что в URL есть `?` (а также `&`, если добавите параметры).

### Опции

| Опция | По умолчанию | Описание |
|---|---:|---|
| `--request-count <N>` | `10` | Количество последовательных запросов |
| `--timeout-ms <MS>` | `60000` | Таймаут одного запроса в миллисекундах |

## Единицы измерения

- **Скорость — только в Mbit/s** (мегабитах в секунду): `1 Mbit/s =
  1 000 000 bit/s`. Других единиц скорости нет.
- **Объём скачанных данных — в MiB**: `1 MiB = 1024² байт`.

Объём считается по **wire bytes** — это байты тела ответа, реально полученные
из сокета, без HTTP-заголовков. Запросы отправляются с `Accept-Encoding:
identity`, чтобы сервер не сжимал ответ. Если сервер всё равно вернул `gzip`
или `br`, утилита считает именно сжатые байты, а в строке запроса появляется
пометка `[gzip]`/`[br]`.

## Как считаются метрики

- Запросы выполняются последовательно. Время запроса измеряется от старта
  запроса до последнего байта тела ответа.
- TTFB (time to first byte) — время от старта запроса до первого байта тела.
  Включает DNS, TCP, TLS и ожидание ответа сервера.
- Среднее время запроса = суммарное время всех запросов / количество запросов.
- Суммарный объём = сумма байт тела ответа, реально полученных из сокета
  (без распаковки и без HTTP-заголовков).
- **Download speed (end-to-end)** = суммарное количество бит / суммарное время
  всех запросов. Включает TTFB, то есть показывает скорость так, как её видит
  пользователь.
- **Transfer speed (body only)** = суммарное количество бит / суммарное время
  передачи тела (от первого до последнего байта). TTFB исключён, поэтому эта
  величина ближе к скорости самого соединения.

Обе скорости агрегатные: это общий объём, делённый на общее время, а не среднее
арифметическое скоростей отдельных запросов. Запросы отправляются с
`Cache-Control: no-store`, чтобы по возможности не измерять кэш.

### Почему не `fetch`

Встроенный `fetch` в Node.js автоматически распаковывает `gzip`/`br`, даже если
запросить `Accept-Encoding: identity`. Поэтому объём из `fetch` — это размер
после распаковки, а не реально переданные по сети байты. Здесь используется
`node:http`/`node:https`, который отдаёт тело как есть, без декодирования.

## Почему скорость может быть ниже тарифа

- Утилита по условию делает **10 последовательных запросов по одному
  соединению**. Один TCP-поток не всегда может загрузить весь канал, особенно
  если сервер ограничивает скорость на соединение.
- Небольшой файл (например, картинка на 3 МБ) не успевает выйти на полную
  скорость: сказываются RTT, TLS-рукопожатие и TCP slow start. Первые запросы
  обычно медленнее последующих.
- CDN или сервер может отдавать файл медленнее вашего канала. Скорость из этой
  утилиты — скорость загрузки конкретного URL, а не максимальная скорость
  интернет-соединения.
- `Download speed (end-to-end)` включает ожидание ответа сервера, а
  `Transfer speed (body only)` — нет. Для сравнения с тарифом провайдера
  полезно смотреть на обе цифры.
- Для оценки тарифа используйте большой файл (100+ МБ) и/или специализированный
  speedtest с несколькими параллельными потоками. Здесь же важен результат
  именно для указанного URL.

## Тесты

```bash
npm test
```

Тесты проверяют разбор аргументов, расчёт среднего времени и скорости в Mbit/s,
полное чтение потока ответа, подсчёт именно сжатых wire bytes вместо
распакованных данных и обработку редиректов.

## Ограничения

- Используется один поток и одно соединение; результат зависит от задержки и
  ограничений сервера.
- Первый запрос включает DNS, TCP и TLS, поэтому обычно медленнее последующих;
  среднее по всем запросам может быть ниже установившейся скорости.
- Upload и ping не измеряются.
- Некоторые серверы и CDN могут отвечать `429` или кэшировать ответы. Для
  стабильных замеров используйте большой файл и URL, который не кэшируется.
- Утилита завершается с ошибкой, если хотя бы один запрос не удался или
  превысил таймаут.
